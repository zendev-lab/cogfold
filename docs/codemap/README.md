# Spark 代码地图

使用浏览器直接打开 `codemap.html`。页面内嵌数据，浏览地图无需服务器、安装依赖或网络。
源码文件可在本地打开；基线源码链接需要联网。托管页面使用基线链接，因为文档服务器
不包含仓库源码目录。

地图用 20 个职责节点组织 `architecture/packages.json` 中的全部包。
守护进程存储在所属应用内单独展开；Hub SQLite 仍是独立的协同数据库。
选择模块可查看上游调用方、下游影响、包归属、外部依赖和代表性测试声明。
搜索支持归组后的文件路径；可选择五条有序工作流，也可切换运行时与构建关系视图。

## 证据与维护

`codemap.json` 负责人工整理的描述、运行时关系、工作流步骤和包分组。
`scripts/codemap.py` 从当前工作区推导归组后的跟踪文件、代表性的 TypeScript
字面量测试声明和生产包依赖，并检查清单中的每个包恰好属于一个父节点。
构建关系描述包依赖，不推断函数调用。原生 Cargo 依赖和开发依赖通过清单文件查看，
不绘制为运行时关系。这里列出的测试是声明，不是执行结果。

独立的 `codemap.html`、`codemap.json` 和 `codemap.lock` 是可在浏览器打开的地图产物。
`apps/spark-docs/public/codemap/` 中的副本由同一来源生成；不要单独编辑或格式化
任一生成版本。`template.html` 是界面源文件。包清单和规范契约仍是权威来源，
地图仅作解释性展示。

```sh
python3 scripts/codemap.py build
python3 scripts/codemap.py check
```

源码行为变化时，复核运行时描述；检查对应源码后再更新基线提交。
生成过程会更新 HTML、SHA-256 证据和 `apps/spark-docs/public/codemap/` 中的三份静态副本，
不要手工修改副本。检查会拒绝过时的清单、路径、测试声明、文件哈希、HTML 和公开资源，
验证的是完整性，不是文字描述的语义正确性。

证据锁定清单描述精确的本地工作区，包括未提交改动；GitHub 链接显示基线提交，
可能与已修改的文件不同。修改后，除源码检查外，还需运行仓库文档规定的组件、浏览器
和文档检查。在实际浏览器中验证五条工作流及模块交互后，才能声明视觉验收通过。

## 浏览器验收

在桌面和窄屏视口下打开独立文件及文档路由，操作全部模块按钮、两种关系视图、五条工作流、
文件名搜索、空结果恢复、键盘导航、源码与测试链接，并检查减少动态效果偏好。
结果和截图保存在本地报告或 CI 产物中。地图验收不代表产品流程或已部署站点验收通过。

托管页面不会为基线提交中不存在的文件生成证据链接，而会标注为本地新增。
可在工作区以文件方式打开地图来阅读这些文件；生成时会根据实际 Git 树重新计算
`baselineMissingPaths`。
